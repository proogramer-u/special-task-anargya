## MEDIUM — implemented

## Persistence and authentication

No external database or dependency installation was needed. `.data/commerce.json` is a private server-side JSON store, outside `public/`, with atomic file replacement and process-wide serialized transactions. It persists products, orders and hashed sessions across server restarts. New stores seed four demo products. No admin password is seeded into source code.

Authentication uses salted Node scrypt hashes and timing-safe comparison. Session tokens are random, stored hashed server-side and expire after eight hours. Cookies are HttpOnly, SameSite=Strict and Secure when accessed through HTTPS. Every admin API independently checks authentication; the protected admin page redirects unauthenticated visitors. Mutations require same-origin JSON requests. Basic in-process rate limits cover login and public order submissions. Body size, strings, integer quantities/prices, product image selection and order status are validated. Confirmation responses, APIs and admin content are marked no-store. Order submission uses an idempotency key paired with its private access token, so a retry does not decrement stock twice.

### Local setup

A random local-only QA password was generated into **ignored** `.data/local-admin-password.txt`. Its salted hash is in **ignored** `.env.local`. Open that local file to sign in at `/admin/login`, or choose your own:

```sh
# Stop the server before changing credentials/store configuration.
node scripts/setup-admin.cjs
npm run build
npm run start -- --port 3003
```

The setup prompt is explicitly marked as visible input. The generated password is never embedded in client source or reported in documentation. To revoke existing sessions after password rotation, stop the server and clear the `sessions` array in the private JSON store before restarting. Do not delete orders/products to rotate credentials.

Environment variables:

| Variable | Requirement | Purpose |
|---|---|---|
| `ADMIN_PASSWORD_HASH` | Required for admin only | `salt:hex` scrypt hash generated by setup script; never NEXT_PUBLIC |
| `COMMERCE_DATA_DIR` | Optional locally; configure on persistent hosting | Private directory; default project `.data` |
| `APP_ORIGIN` | Recommended before deployment behind a proxy | Exact HTTPS origin for mutation checks |

`.env.example` contains empty/documented settings only. `.env.local`, `.data`, QA previews and generated build output are ignored.

**Hosting boundary:** the store supports one Node process on writable persistent disk. It is not a shared database for serverless, ephemeral disk, multiple workers or replicas. Before deploying to those environments, migrate the transaction/storage interface to a durable database. Local rate limits likewise need shared enforcement for multiple replicas. This is a functional special-task demo, not a production commerce platform. Back up the private store securely; use fictional customer details for evaluation.
